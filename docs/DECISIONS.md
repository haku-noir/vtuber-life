# 実装判断

## M1: 決定的な実行と保存の土台（2026-10-18）

対象は仕様第01・02・07・17・18章の基盤。ゲームの人物生成、週次シミュレーション、選択の解決、画面は後続マイルストーンで実装する。AT06・AT14・AT15・AT19は基盤の部分試験であり、ゲーム全体の受入完了を意味しない。暦はAT23、表示乱数分離はAT05、同接の保存形式はAT07の基盤も検査する。

### 乱数

- `src/rng.js` はmulberry32と、UTF-16コード単位のFNV-1aを使う。版は `mulberry32-fnv1a-utf16-v1`。シード・用途・追加キーをJSON配列で区切り、数値と文字列、キーの連結順を区別する。暗号や改ざん検出用ではない。
- 人物・世界・活動・私生活・後日談・公開表現・表示・V設定のストリームを分離する。用途内のイベントID・相対週・対象ID等は `fork(...keys)` に渡す。forkは親の消費回数に依存しない。同じキーの再作成は同じ列の先頭へ戻るため、途中再開には `snapshot()` と `restoreRng()` を使う。
- 整数抽選は棄却法。重みは呼出側がデータから明示し、null・負数・非有限値・全ゼロを拒否する。未決の分布を一様とみなす暗黙の補完はしない。

### パラメータ

- `loadParams(readText)` は同梱JSONの読込み関数を注入できる。ブラウザで省略した場合だけ、モジュールに対して相対指定したローカルJSONをfetchする。Nodeでは `url => readFile(url, "utf8")` を渡す。外部サービスには接続しない。
- `parseParams` は版・必須コレクション・重複ID・列ID・数値重み・根拠区分を検証し、全階層を凍結する。注記を含む原文の根拠区分は、既存の6区分との対応だけ検査してそのまま保持する。LPの「—」と廃止行の根拠なしは既存資料の表現として許容する。
- nullのイベント重みを補完せず、廃止IDも原本には保持する。新規候補は `getCandidates` で廃止行を除く。重い出来事を除外・減量する設定は設けない。
- 候補IDの参照は明示的な `*Id` / `*Ids`、整合表のID・範囲、職業の生活効果表を検査する。研究の `sourceIds` は別名前空間であり、形式を検査するが、このローダーは研究文書の書誌を読み込まない。文章全体をゲーム用の参照や表示文に変換しない。実在の公開例を含む原本の列をそのまま画面や人物へ流用しない。
- 観察期間はP-17の「観察期間」行の「からN暦月」を限定的に読み取る。現在は180。数値列がないための明示的なアダプターで、文面が変わった場合はエラーにし、コード内の既定値へ逃がさない。他の未決パラメータは本段階では解釈しない。

### 暦と境界

- ISO日付をUTCの日番号へ変換する。ローカル時刻や夏時間に依存させず、期間は開始を含み終了を含まない `[start, end)` とする。月加算は元の日を対象月の末日に丸める。観察終了日は初公開日から一度にN暦月を加算し、毎月の末日丸めによるずれを避ける。
- `nextBoundary` は次の7日境界・月初・イベント日・終了日を返す。同日の種類をすべて返し、`advanceCalendar` は月またぎでも週の起点を維持する。最終端数週に `partial: true` を付ける。返した暦と途中週をまとめて保存する責務は後続の実行ループが持つ。
- イベント予定は現在日より未来だけを渡す。現在日の選択・イベントは実行ループが解決し、消費済み予定を除いてから次の境界へ進める。暦関数自体は選択・支払い・イベントを実行しない。

### 保存と金銭

- M1の保存形式は `save-0.1.0`、計算は `sim-0.1.0`、内容は既存の `0.5.0`。調整・命名・たねの形式にも個別の0.1.0識別子を付ける。まだ読み込まない統計版は `not-loaded` とし、統計の値をセーブに複製しない。これらは基盤の識別子であり、命名候補やたねコード機能の完成を意味しない。
- 全7版を期待値と照合する。旧形式の実装がないため自動移行はせず、不明版を拒否する。将来の統計版等の対応時には期待版とスキーマを明示して更新する。
- `createSave` は開始日とseedを受け取る基盤用の器。人物・開始設定のテンプレートはM2までnull、実行記録は空である。人物・作品・チャンネル・イベントのID表、参照、公開日、週の位置、非負の人数・再生、同接のnullと分子・分母、選択の再開段階、適用済み効果、乱数状態を検査する。
- 金銭の単位は安全な整数の円。端数は本段階では拒否する。将来の収支計算が端数を生む場合は、その計算境界で丸め規則を版管理する。無断借金となる残高マイナスと安全整数の超過を拒否する。
- 取引は `yearMonth + transactionId` で一意。`applyTransaction` は同一内容の再適用を何もしない操作にし、内容の違う再適用を拒否する。`settleMonth` は取引列を検証し、全件成功した新しい台帳だけを返す。例外時は元の台帳を変更しない。精算済み月に新しい取引を追加しない。
- `serializeSave` はJSON化の前にNaN・循環・不正な型を拒否する。`loadSave` は `{ok, save}` または `{ok: false, error}` を返し、原本・現行状態・ストレージを書き換えない。`saveToStorage` は検証完了後に注入されたWeb Storageへ1回だけ書き、失敗を返す。保存失敗の通知、消去の注意、ファイル入出力のUIは後続で接続する。
- 読込み上限は400万UTF-16コード単位、配列10万要素、文字列16384単位、深さ40、総ノード30万。実測前の防御的な技術上限であり、人口・作品数の統計ではない。M3以降の最大周回を計測して見直す。

### ローカル配信と検証

- `npm start` の静的サーバーは127.0.0.1、既定ポート8080、`PORT`で変更可能。`/` はweb/index.html、`/src/`はES Modules、同梱JSONは指定した2ファイルだけを配信する。パストラバーサル・隠しパス・配信ルート外のリンク先を拒否する。外部依存なし。
- M1にはweb/がないため、トップは「ゲーム画面は後続で実装」の簡素な案内を返す。web/index.htmlが追加されればそのまま配信する。ゲームの操作画面はここでは追加しない。
- 検証コマンドは `npm test`（Node.js 22以上）。追加の4テストファイルはnode:testで実行する。HTTPテストはループバックだけに接続する。
- この作業環境ではNode.jsとnpmが見つからず、`npm test`を実行できなかった。補助検証として同じロジックとテストのコールバックをV8で実行した。Nodeのimport、ファイルI/O、URL、assert/test登録を代替した検査であり、正式なnode:test実行やHTTPサーバー試験の代わりにはしない。統合前にNode環境で `npm test` と `npm start` を確認する必要がある。

## M2: 開始設定の部分実装と未確定データ（2026-10-18）

**M2は未完了。** 今回の変更対象には `params.json` が含まれない。P-18の実年齢は「18歳以上。分布は未決（値を置かない）」、基本気質は「分布は未決」と明記されている。一様分布・中央値・仮の年齢上限で補完しない。名称台帳、外見素材、BGカテゴリと候補の対応・年代/年齢の成立条件、生活条件・経験・所属・活動方針、NaturalSpeechの候補、CSの自動文章/素材にも実行用データがない。研究欄の実在名や説明文を候補に転用しない。

- `generatePerson(params, personSeed)` は開始年と年内の日をP-18から抽選し、未確定項目をnullとした凍結済みの草案と項目別の不足理由を返す。これはプレイ可能なPersonTemplateの完成を意味しない。人物を編集・再抽選するAPIはない。全初期項目の由来に未決と確定を区別して記録する。
- `createSetup(params, {seed, entry, overrides})` はQS共通の編集セッションを作る。`snapshot()` の `ready` は現在の同梱データでは必ずfalse。入口だけを変えても人物・Vテンプレートは変わらない。`setEntry` でQS2/3に移った後、Vの編集・再抽選・ロックを利用できる。RUNNING遷移、QS確認カード、人物ダイジェストは未実装。
- 確定データのあるSP・JB・ST・一人称・呼びかけ・口癖を生成する。PTは初期の自然体（主・副null）、夢は未設定、おまかせ重大選択はOFF。各重みと整合倍率はJSONを読む。自動選択で禁止された組合せも明示的な上書きは許す。ST09の前の肩書き不足は原因を返し、自動修正しない。JBから中の人の職歴・資格・能力を生成しない。
- CSの列内候補は `CS01_00` のような0始まりの位置IDにする。この対応は内容版に属し、並べ替える場合は版を更新する。「その他」「名前呼び」「ファンネームで呼ぶ」等、未収録の別データが必要な候補は自動候補にしない。口癖は最初だけ「なし」、項目再抽選では既存の具体的候補から一様に選ぶ。未収録項目の操作では値を捏造せず、不足理由が残る。
- ロックは外見・V設定・活動方針の3グループ。再抽選の項目シードはVシード・変更回数・項目名から導出し、ロック中の値とシードは維持する。項目再抽選では他の項目を変えない。ロックした上流/下流項目との自動抽選の禁止組合せも除外する。プレイヤーが作ったギャップを拒否する根拠にはしない。
- 取り消しは編集セッションのクロージャに直前10件を保持する。保存テンプレートやたねコードに履歴を含めない。取り消しで乱数キーと変更回数も戻し、同じ操作を再度行えば同じ候補になる。自由入力はUnicodeコードポイントで長さを検査し、制御文字・改行・URLを除く。文字列としてのみ保持し、HTMLや式として評価しない。

### 世帯の単体生成

- `generateHousehold(params, {personSeed, age, background})` は人物生成器が将来決める年齢とBGを受け取る内部ロジックであり、プレイヤーの人物編集機能ではない。P-20の数値はJSONの文章列から限定的な正規表現で読み、書式不一致はエラーにする。人物草案には年齢/BGがないため、まだ接続しない。
- 年齢帯の「既婚」基準値を法律婚とパートナー同居の合計確率として扱い、その後P-20の0.9/0.1の内訳を適用する。AT139の部品試験もこの合計を数える。開始年による補正はなく、同じ人物シード・相対年齢・BGから同じ家族になる。子供の個人名・顔・学校は生成しない。
- 本体37.3の「既婚・パートナー同居の場合だけ子供を生成」を優先し、P-20のひとり親確率は適用しない。BG22の「子供必須」と既婚確率0.85の非同居分岐は両立規則がないため、同BGの世帯生成を明示的に止める。黙ってBGや婚姻状態を交換しない。
- 子の年齢の上限が0未満となる18～19歳では子を生成しない。不成立の組合せを生成段階で除く37.3に従う。「3人以上」は人数の追加分布がないため下限の3人で表現する。最年少の子に全負荷、その他にP-20の限界負荷を適用し、分担比を引く。この部品では時間のみ計算し、能力は変更しない。birthRoleは将来子の計画がある時に抽選するため、開始時はnot_applicableとする。

### たねコードの部品

- `seedcode.js` は厳密な許可フィールドだけを持つレコードの符号化/復号を実装する。形式版は `seed-setup-0.1.0`。`VTL5-` と0/O/1/I/Lを除いた31文字の可変長4文字区切り、末尾1検査文字。上限16384文字。仕様の約29文字は案であり、任意の項目シード・上書き・ロックを通信なしで可逆に持つには不足するため可変長とした。検査文字は誤入力検出用であり、暗号的な認証ではない。
- 世界・人物・Vのシード、全版、開始年の一様モード、ロック、項目の変更回数、候補IDだけを格納する。依存項目を後で変えても復元できるよう、最終候補のselectionsも保持する。自由入力は両候補マップから除き、読み込み側の自動候補への復帰通知を返す。端末情報・プレイ中の選択・セーブ・文章は受け付けない。未知フィールド・版・不正な候補・構造・検査文字は拒否する。
- 現在の不完全な人物草案から `exportSeedCode()` は利用できず、取り込みも完成した開始設定として公開しない（特にNaturalSpeech欠落を補わない）。コーデック単体の往復は検証できるが、AT98の完全な開始設定復元、AT100の名称再確認/置換はデータ整備後に接続する。
