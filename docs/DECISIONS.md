# 実装判断

## 仕上げM3: 育児費と健康休養の復帰（2026-10-19）

- EV14・EV25・EV86・EV87・EV88は月ごとに1%・1%・1.5%・0.5%・1.5%、同一IDの再発間隔は12・12・12・24・6か月とする。すべて統計値ではなく仮置きで、M2のJSON定義にparams.mdの説明を揃える。
- 育児費はP-22の `money.childcareMonthlyYen=30000` を子の人数分、実行時の生活費に加える。統計値ではなく仮置き。初期人物・生活費テンプレートを固定したまま、初期の子と後から増えた子に適用する。既存の月初会計に合わせ、その月を開く時点の人数を採用し、開いた後の誕生は次月から反映する。年齢・分担による減額は定義しない。部分月は既存の日割り、資金不足は未払い額に計上し、借金にしない。
- 健康休養はP-22の `healthLeave.months=1` 暦月を仮置きする。統計値や医学的目安ではなく、休む選択で永久に活動が止まる状態を解消するための調整。復帰日にEV26をキュー先頭へ一度だけ入れ、回答後に通常または低頻度で再開する。育児休業中はEV96の予定を保持する。旧保存の復帰日nullは最初の処理境界から期間を設定し、過去の選択・会計を書き換えない。
- spec-main.md 2.1節の1行修正は今回の契約外のため未対応のまま。M4後の正式検証成功を記録に反映し、旧時間・未設定重み・育児費未定義の記述を現状に揃える。
- M3実装環境ではNode/npmが見つからず `npm test` は起動できなかった。V8上でES Modules・Node検証関数・ファイル読込みをメモリ内で代替した補助実行では、sim/eventsの39試験と時計・QS1完走などの既存7試験が修正後に成功した。正式なnpm全件試験・HTTP・実ブラウザ検証とは区別し、今回の正式検証は後続の検証担当に残す。

## 仕上げM1: 1倍速で約60分の観察期間（2026-10-19）

- 自動送りはP-17の仮置き値を平均約20秒／暦月相当に変更する。統計ではなく観察体験の調整値であり、180暦月×20秒＝約60分（停止・選択待ちを除く）とする。0.5・1・2・4倍は維持し、既存のparams読込みと暦月の日数による待機時間の配分を使う。
- 時計の試験だけは複製したパラメータのイベント抽選率を0にし、速度・停止・描画操作とタイマーの累計時間を検証する。別の完走試験は本番パラメータを使い、重大選択へ同じ方針で回答した結果をバッチ実行と比較する。回答APIのない観察コントローラーは回答済み状態で作り直し、本番の操作機能の追加とは扱わない。
- M4ではP-17の「一周の体感時間」も1倍速で約60分に揃え、停止・選択待ち・後日談を除く観察期間の所要時間とする。spec-main.md 2.1節はM4の変更契約でも対象外となり、「一周5～10分」→「約60分」、「約1.5秒／月」→「約20秒／月」の1行変更は未対応。
- M1・M4実装時はNode/npmが見つからず全件試験を起動できなかった。その後、検証担当による `npm test` 全件成功がM1・M2・M4の完了記録に残っている。実装時の未実行記録と後続の正式検証を区別する。

## M13: 任意の夢・後日談・人生記録・別年代比較（2026-10-18）

- `dreams.js` はP-05の現行12候補を読み、D12と拡張候補を新規選択から除く。登録者・原曲再生の閾値はJSONの達成条件文から限定的に抽出し、解釈できない値を補完しない。D03の表示名は実在施設名を避け「象徴的な会場」とする。会場属性・役割・実開催、公式OP公開、正式許諾された主役級ゲームの完成公開を判定し、予約や予告を到達にしない。
- DreamInstanceと客観的なAchievementRecordを分離する。選択・変更・保留・解除は無償で、判定は境界と明示的な公開記録の確定時に行い、乱数を消費しない。到達キーは周回・条件版・条件ID・対象・閾値・役割・セットリスト条件で一意にする。複数閾値は一つの演出バッチにまとめ、既存の重大選択を遮らない。回想は保存済みのイベントIDだけを参照し、公開した夢と観察者だけが見る夢を分ける。
- 公演・OP・ゲームの実施記録用に `recordAchievementEvent` を提供する。原曲再生はWorkのoriginal・primarySinger・countingReleaseId、Releaseのofficial・fullLength・kind・serviceを明示した単一公開物に限る。通常の音楽作品を根拠なく原曲認定しない。企画の自動提案・制作・出演費・公開のイベント連鎖は、未確定の発生重みを補わず後続のコンテンツ工程に残す。この工程のAT44～54は証拠判定のロジック検証であり、全候補への自然到達や画面操作の完了を表さない。
- 最終終了は最後の到達判定、未達の区切り、EpilogueRecordの生成の順とし、EV27も同じ経路へ接続する。後日談は既存の仕事・家庭・作品を参照し、追加した将来の文章を別欄で保存する。未登場の家族・成功・未来の数字は生成しない。次の進行または `completeEpilogue` でRESULTへ移り、保存済み年表・作品・グラフを参照するRunSummaryを作る。期間上限・`stopObservation` は活動継続のスナップショットとし、卒業文や後日談を使わない。
- 転生は本人の技術・年齢基準・負荷・台帳・家庭・総観察期間を維持し、0人からの新チャンネルを先頭に追加する。旧作品は帰属と履歴を保持し、利用条件の実装前なので新名義で再利用・再集計しない。日次エンジンへ現名義の作品だけを渡し、生成IDと制作支払IDをチャンネル別にする。週途中の旧名義はchannelWeekSegmentsに保存し、observedStartDateで実際の観測開始を区別する。チャンネルの夢は明示的なretargetまたはholdで引き継ぎ、旧人数を合算しない。新しい名前・外見の編集と権利別の作品継続は今回の最小転生APIの対象外。

## M1: 決定的な実行と保存の土台（2026-10-18）

対象は仕様第01・02・07・17・18章の基盤。ゲームの人物生成、週次シミュレーション、選択の解決、画面は後続マイルストーンで実装する。AT06・AT14・AT15・AT19は基盤の部分試験であり、ゲーム全体の受入完了を意味しない。暦はAT23、表示乱数分離はAT05、同接の保存形式はAT07の基盤も検査する。

### 乱数

- `src/rng.js` はmulberry32と、UTF-16コード単位のFNV-1aを使う。版は `mulberry32-fnv1a-utf16-v1`。シード・用途・追加キーをJSON配列で区切り、数値と文字列、キーの連結順を区別する。暗号や改ざん検出用ではない。

- 整数抽選は棄却法。重みは呼出側がデータから明示し、null・負数・非有限値・全ゼロを拒否する。未決の分布を一様とみなす暗黙の補完はしない。

### パラメータ

- `loadParams(readText)` は同梱JSONの読込み関数を注入できる。ブラウザで省略した場合だけ、モジュールに対して相対指定したローカルJSONをfetchする。Nodeでは `url => readFile(url, "utf8")` を渡す。外部サービスには接続しない。
- `parseParams` は版・必須コレクション・重複ID・列ID・数値重み・根拠区分を検証し、全階層を凍結する。注記を含む原文の根拠区分は、既存の6区分との対応だけ検査してそのまま保持する。LPの「—」と廃止行の根拠なしは既存資料の表現として許容する。
- nullのイベント重みを補完せず、廃止IDも原本には保持する。新規候補は `getCandidates` で廃止行を除く。重い出来事を除外・減量する設定は設けない。
- 候補IDの参照は明示的な `*Id` / `*Ids`、整合表のID・範囲、職業の生活効果表を検査する。研究の `sourceIds` は別名前空間であり、形式を検査するが、このローダーは研究文書の書誌を読み込まない。文章全体をゲーム用の参照や表示文に変換しない。実在の公開例を含む原本の列をそのまま画面や人物へ流用しない。
- 観察期間はP-17の「観察期間」行の「からN暦月」を限定的に読み取る。現在は180。数値列がないための明示的なアダプターで、文面が変わった場合はエラーにし、コード内の既定値へ逃がさない。他の未決パラメータは本段階では解釈しない。

### 暦と境界

- ISO日付をUTCの日番号へ変換する。ローカル時刻や夏時間に依存させず、期間は開始を含み終了を含まない `[start, end)` とする。月加算は元の日を対象月の末日に丸める。観察終了日は初公開日から一度にN暦月を加算し、毎月の末日丸めによるずれを避ける。

- CSの列内候補は `CS01_00` のような0始まりの位置IDにする。この対応は内容版に属し、並べ替える場合は版を更新する。「その他」「名前呼び」「ファンネームで呼ぶ」等、未収録の別データが必要な候補は自動候補にしない。口癖は最初だけ「なし」、項目再抽選では既存の具体的候補から一様に選ぶ。未収録項目の操作では値を捏造せず、不足理由が残る。
- ロックは外見・V設定・活動方針の3グループ。ロックが防ぐのは再抽選だけで、明示的な上書きは可能とする。選んだ値を再抽選から守りつつ編集できるようにするためで、上書きは履歴・playerOverrideに残し、取り消し可能とする。再抽選の項目シードはVシード・変更回数・項目名から導出し、ロック中の値とシードは維持する。項目再抽選では他の項目を変えない。ロックした上流/下流項目との自動抽選の禁止組合せも除外する。プレイヤーが作ったギャップを拒否する根拠にはしない。
- 取り消しは編集セッションのクロージャに直前10件を保持する。保存テンプレートやたねコードに履歴を含めない。取り消しで乱数キーと変更回数も戻し、同じ操作を再度行えば同じ候補になる。自由入力はUnicodeコードポイントで長さを検査し、制御文字・改行・URLを除く。文字列としてのみ保持し、HTMLや式として評価しない。
