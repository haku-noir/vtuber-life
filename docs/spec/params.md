## 0. 読み方と管理規則

### 0.1 正となる文書

| 内容 | 正とする文書 |
| --- | --- |
| 規則・制限・禁止事項（例：能力を直接上げない、重い出来事の固定の作法、実在名称を使わない） | 仕様書 |
| 候補の名称・反映例・根拠・区分・数値・重み | 本書（とJSON） |
| 両者が食い違う場合 | 仕様書の規則を優先し、本書の値を直す。値の変更でAT（仕様書第22章）を破らない |

### 0.2 根拠区分

| 区分 | 意味 |
| --- | --- |
| 統計 | 出典が数えた値をそのまま記録。定義・範囲は出典に従う |
| 推定 | 本書側の計算を含む。式と入力を明記 |
| 仮置き | ゲーム調整用の値。現実の値ではない。JSONでは `evidenceClass: "仮置き"`、重みが未定の場合は `value: null` |
| 調査由来 | 候補の存在を公開情報で確認したもの（件数は重みに使わない） |
| ゲーム独自 | 本作が補った候補 |
| ゲーム設定（v0.4） | v0.4以前から継続する候補。根拠列があればその範囲で確認済み |

### 0.3 IDと変更の規則

- IDは再利用しない。削除する候補は「廃止」と記し、番号を詰めない。
- 節番号P-xxは仕様書の章・節番号と独立である。仕様書の章・節番号（例：第30.4節）は分割前と同じで、移した箇所には参照文を置いた。
- 値を変えたらcontentVersion（またはbalanceVersion）を上げ、仕様書第18章の版の規則に従う。

### P-18b　V候補・開発用名称台帳

`vDefaults.nameLedger` は有限のフルネーム3件と読みを持つ**DRAFT台帳**。全件外部確認未実施で、確認者・確認日・検索式・URLを捏造せず、未確認範囲を記録する。`releaseReady:false` の開発状態だけでDRAFT候補を扱う。第24章の公開用名称確認は未完了であり、QS1の `ready` はロジック上の初期値成立を表す。公開可能との判定ではない。衝突・要再確認・未知の候補は種コード取込時にも拒否する。

候補IDは既存の種コードに保存できる固定ID。CS90_nnは名前、CS91_nnは外見、CS92_nnは主活動、CS93_nnは継続方針を表す内部名前空間であり、仕様のCS項目を追加する番号ではない。他はCS03～CS13の既存項目に対応する。候補のIDは再利用せず、値と重みはJSONに置く。
